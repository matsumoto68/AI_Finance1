## 2. システム概要

### 2.1 目的

担当者から展開された手動Linuxコマンド手順書に記載されたコマンドをシェルスクリプト化し、サーバA・サーバBの2台に対するリリース作業を統合的に自動実行する。サーバAでのローカル実行に加え、サーバBへのSCP資材転送・SSHリモート実行をオーケストレーターシェルで一括制御する。

### 2.2 実行環境

| 項目 | 内容 |
|------|------|
| OS | Linux |
| シェル | bash |
| 実行ユーザー | 一般ユーザー（$プロンプト）/ rootユーザー（#プロンプト） |
| 接続方法 | Teraterm（SSH接続） |
| サーバ構成 | サーバA（主系・オーケストレーター実行元）、サーバB（従系・リモート実行先） |
| サーバ間通信 | SCP（資材転送）、SSH（リモート実行） |

### 2.3 システム構成

```
担当者
  │
  │ 手動コマンド手順書を展開（サーバA・サーバB各向け）
  ▼
開発チーム
  │
  │ Kiroを使用してシェルスクリプトを自動生成・レビュー
  ▼
シェルスクリプト群
  ├─ CommandA.sh（サーバA向けメインシェル）
  ├─ CommandB.sh（サーバB向けメインシェル）
  ├─ release_all.sh（オーケストレーターシェル）
  └─ deploy_multi.sh（複数サーバ向け資材配置シェル）
  │
  │ deploy_multi.shによりLinux環境へ配置
  ▼
サーバA（Linux環境）
  │
  ├─ release_all.sh 実行
  │     │
  │     ├─ [直接実行] CommandA.sh → ログ出力
  │     │
  │     ├─ [SCP転送] CommandB.sh → サーバBへ転送
  │     │
  │     └─ [SSHリモート実行] サーバB上のCommandB.sh → ログ出力
  │
  ▼
サーバB（Linux環境）
  │
  │ CommandB.sh リモート実行
  ▼
実行ログ出力（サーバA・サーバB各上）
```

## 3. シェルスクリプト仕様

### 3.1 ファイル構成

| ファイル名 | 種別 | 配置サーバ | 説明 |
|-----------|------|----------|------|
| `CommandA.sh` | メインシェル | サーバA | サーバA向け全自動化コマンドを実行するメインスクリプト |
| `CommandB.sh` | メインシェル | サーバB | サーバB向けコマンドを実行するメインスクリプト |
| `release_all.sh` | オーケストレーターシェル | サーバA | サーバA実行＋サーバBへのSCP転送・SSHリモート実行を一括制御 |
| `deploy_multi.sh` | 資材配置シェル | サーバA（実行元） | サーバA・サーバB両方へ資材を配置する複数サーバ向け配置シェル |

### 3.2 配置ディレクトリ

#### サーバA

| 種別 | パス | 説明 |
|------|------|------|
| スクリプト配置先 | `/opt/release/scripts/` | 全シェルスクリプトの配置ディレクトリ |
| ログ出力先 | `/var/log/release/` | 実行ログの出力ディレクトリ（資材配置フォルダとは分離） |
| 作業ディレクトリ | `/tmp/testdir/` | ファイル・ディレクトリ操作の対象ディレクトリ |

#### サーバB

| 種別 | パス | 説明 |
|------|------|------|
| スクリプト配置先 | `/opt/release/scripts/` | SCPで転送されたCommandB.shの配置ディレクトリ |
| ログ出力先 | `/var/log/release/` | CommandB.sh実行ログの出力ディレクトリ |
| 作業ディレクトリ | `/tmp/testdir/` | ファイル・ディレクトリ操作の対象ディレクトリ |

### 3.3 実行権限

| ファイル | 権限 | 説明 |
|----------|------|------|
| `CommandA.sh` | `755` | オーナー実行可・グループ/その他は読み取り・実行可 |
| `CommandB.sh` | `755` | 同上 |
| `release_all.sh` | `755` | 同上 |
| `deploy_multi.sh` | `755` | 同上 |

## 4. 処理概要

### 4.1 全体処理フロー

```
開始（サーバA上で操作）
  │
  ├─ [1] deploy_multi.sh 実行（資材配置）
  │       ├─ CommandA.sh を サーバA /opt/release/scripts/ へ配置
  │       ├─ CommandB.sh を サーバA /opt/release/scripts/ へ配置
  │       ├─ release_all.sh を サーバA /opt/release/scripts/ へ配置
  │       └─ 実行権限の付与（chmod 755）
  │
  └─ [2] release_all.sh 実行（オーケストレーター）
          │
          ├─ [2-1] 事前チェック（接続情報・環境確認）
          │
          ├─ [2-2] CommandA.sh をサーバA上でローカル実行
          │         └─ ログ出力: /var/log/release/CommandA_*.log
          │
          ├─ [2-3] SCP: CommandB.sh をサーバA → サーバB へ転送
          │         └─ 転送先: /opt/release/scripts/CommandB.sh
          │
          └─ [2-4] SSH: サーバB上のCommandB.sh をリモート実行
                    └─ ログ出力: /var/log/release/CommandB_*.log（サーバB上）
```

### 4.2 CommandA.sh 処理フロー

```
開始
  │
  ├─ [1] 事前チェック（実行環境・権限確認）
  │
  ├─ [2] ディレクトリ操作処理
  │     ├─ ディレクトリ作成
  │     ├─ ディレクトリ移動
  │     ├─ ディレクトリコピー
  │     └─ ディレクトリ削除
  │
  ├─ [3] ファイル操作処理
  │     ├─ ファイル作成
  │     ├─ ファイル内容確認
  │     ├─ ファイルコピー
  │     ├─ ファイル移動（リネーム）
  │     └─ ファイル削除
  │
  ├─ [4] サービス操作処理
  │     ├─ サービス起動
  │     ├─ 起動確認
  │     ├─ サービス停止
  │     ├─ 停止確認
  │     └─ サービス状態確認
  │
  ├─ [5] 一覧表示・権限変更処理
  │
  └─ 終了（正常終了 / エラー終了）
```

### 4.3 CommandB.sh 処理フロー

CommandB.shはCommandA.shと同等の処理構造（カテゴリ1〜4）を持つ。担当者から展開されるサーバB向けコマンド手順書に基づき、以下の処理カテゴリを実装する。

| カテゴリ | 処理内容 | CommandA.shとの関係 |
|----------|---------|---------------------|
| カテゴリ1 | ディレクトリ操作処理 | 同等構造（作業ディレクトリのパスはサーバB環境に合わせて設定） |
| カテゴリ2 | ファイル操作処理 | 同等構造 |
| カテゴリ3 | サービス操作処理 | 同等構造（対象サービスはサーバB環境に合わせて設定） |
| カテゴリ4 | 一覧表示・権限変更処理 | 同等構造 |

### 4.4 release_all.sh 処理フロー（オーケストレーター）

```
開始
  │
  ├─ [1] 事前チェック
  │       ├─ 接続情報（ホスト名・ユーザー名・秘密鍵パス）の取得
  │       ├─ サーバBへのSSH接続確認
  │       └─ 必要ファイルの存在確認
  │
  ├─ [2] サーバA処理
  │       └─ CommandA.sh をローカル実行
  │           ├─ 正常終了 → [3] へ進む
  │           └─ エラー終了 → エラーログ出力・処理中断（サーバB処理は実行しない）
  │
  ├─ [3] サーバBへの資材転送
  │       └─ SCP: CommandB.sh をサーバBの /opt/release/scripts/ へ転送
  │           ├─ 正常終了 → [4] へ進む
  │           └─ エラー終了 → エラーログ出力・処理中断
  │
  ├─ [4] サーバBリモート実行
  │       └─ SSH: サーバB上の CommandB.sh をリモート実行
  │           ├─ 正常終了 → [5] へ進む
  │           └─ エラー終了 → サーバBのエラー内容をサーバAのログに記録・処理終了
  │
  └─ [5] 終了（正常終了）
```

### 4.6 サーバB向けコマンド構成

サーバB向けCommandB.shの自動化対象コマンドは、担当者から展開されるサーバB向けコマンド手順書に基づき定義する。処理カテゴリ（カテゴリ1〜4）はCommandA.shと同等の構造であり、サーバB環境に合わせてパス・対象サービス等を設定する。

### 4.7 release_all.sh 固有コマンド一覧

| 項番 | コマンドの内容 | Linuxコマンド | 正常ReturnCode | エラー条件 |
|------|--------------|--------------|---------------|------------|

## 6. エラーハンドリング

### 6.1 エラー検出方式

各コマンド実行後に以下の2軸でエラーを検出する。

| 検出方式 | 内容 |
|----------|------|
| ReturnCode チェック | コマンドの終了コード（$?）を確認。正常値以外はエラーとして処理 |
| 結果出力確認文字チェック | コマンド出力に特定の文字列が含まれるかを確認（`grep`を使用） |

### 6.2 エラー発生時の動作

#### CommandA.sh / CommandB.sh

| 動作 | 内容 |
|------|------|
| ログ出力 | エラー内容・コマンド名・ReturnCode を詳細ログに記録 |
| 処理中断 | エラー発生時点で以降の処理を中断し、シェルを終了する（`exit 1`） |
| メッセージ出力 | エラー内容をシェル実行ログに出力する |

#### release_all.sh（オーケストレーター固有）

| 動作 | 内容 |
|------|------|
| CommandA.sh 失敗時 | エラーログ出力後、サーバBへの処理（SCP転送・リモート実行）を一切実行せずに終了する（`exit 1`） |
| SCP転送失敗時 | エラーログ出力後、以降のSSHリモート実行を中断して終了する（`exit 1`） |
| SSHリモート実行失敗時 | サーバBのエラー内容をサーバAのオーケストレーターログに記録して終了する（`exit 1`） |
| SSH接続確認失敗時 | エラーログ出力後、以降の全処理を中断して終了する（`exit 1`） |

### 6.3 エラーメッセージ一覧（CommandA.sh / CommandB.sh）

| 項番 | エラー内容 | 確認文字 | 対処 |
|------|-----------|---------|------|
| 2 | ディレクトリ既存 | `File exists` | エラーログ出力・処理中断 |
| 3 | 権限なし | `Permission denied` | エラーログ出力・処理中断 |
| 8 | ディレクトリ不存在 | `No such file or directory` | エラーログ出力・処理中断 |
| 14 | ファイル不存在 | `No such file or directory` | エラーログ出力・処理中断 |
| 16 | ディレクトリ非空 | `Directory not empty` | エラーログ出力・処理中断 |
| 19 | サービス起動失敗 | `Failed to start` / `Failed` | エラーログ出力・処理中断 |

### 6.4 エラーメッセージ一覧（release_all.sh）

| 項番 | エラー内容 | 確認文字 | 対処 |
|------|-----------|---------|------|
| O-1 | SSH接続確認失敗 | `ok` が含まれない | エラーログ出力・全処理中断 |
| O-2 | SCP転送失敗 | - （RCチェック） | エラーログ出力・処理中断 |

| - | CommandA.sh 失敗 | - （RCチェック） | エラーログ出力・サーバB処理を実行せずに終了 |

## 7. 資材配置シェル仕様（deploy_multi.sh）

### 7.1 概要

試験実施前に `CommandA.sh`・`CommandB.sh`・`release_all.sh` をLinux環境の所定ディレクトリへ配置するためのシェルスクリプト。単一サーバ版（`deploy_CommandA.sh`）を複数サーバ対応に拡張したもの。

### 7.2 処理内容

```
開始
  │
  ├─ [1] 配置先ディレクトリの存在確認（サーバA: /opt/release/scripts/）
  │       存在しない場合 → ディレクトリを作成してから続行
  │
  ├─ [2] CommandA.sh を配置先へコピー
  │
  ├─ [3] CommandB.sh を配置先へコピー
  │
  ├─ [4] release_all.sh を配置先へコピー
  │
  ├─ [5] 各ファイルへ実行権限の付与（chmod 755）
  │
  └─ 終了
```

### 7.3 入出力

| 種別 | 内容 |
|------|------|
| 入力 | `CommandA.sh`、`CommandB.sh`、`release_all.sh`（カレントディレクトリに配置） |
| 配置先 | `/opt/release/scripts/CommandA.sh` |
|  | `/opt/release/scripts/CommandB.sh` |
|  | `/opt/release/scripts/release_all.sh` |
| 実行権限 | `755` |

## 8. 接続情報管理

### 8.1 基本方針

接続情報（ホスト名・ユーザー名・秘密鍵パス）はシェルスクリプト内にハードコードしない。設定ファイルまたは実行時パラメータとして外部から指定する。

### 8.2 接続情報パラメータ

| パラメータ | 説明 | 例 |
|-----------|------|---|
| ホスト名 | サーバBの接続先ホスト名またはIPアドレス | `<SERVER_B_HOST>` |
| ユーザー名 | サーバBへのSSH接続ユーザー | `<SERVER_B_USER>` |
| 秘密鍵パス | SSH認証に使用する秘密鍵ファイルのパス | `<SERVER_B_KEY>` |

> ※ 上記はプレースホルダーであり、実際の値は開発チームが手動で差し替える。機密情報（本番IPアドレス・パスワード・SSH秘密鍵等）はKiroへの入力を禁止する。

## 9. 制約・前提条件

| # | 区分 | 内容 |
|---|------|------|
| 1 | 前提 | サーバAへの SSH 接続が確立されていること |
| 2 | 前提 | サーバAからサーバBへの SSH/SCP 接続が確立されていること（公開鍵認証設定済み） |
| 3 | 前提 | 実行ユーザーが `/tmp/testdir` への書き込み権限を持つこと（サーバA・サーバB共通） |
| 4 | 前提 | `systemctl` コマンドが使用可能であること（サーバA・サーバB共通） |
| 5 | 前提 | サーバBに `/opt/release/scripts/` ディレクトリへの書き込み権限があること |
| 6 | 制約 | `/root/` 配下へのディレクトリ作成は権限エラーが発生する（意図的なエラーテストケース） |
| 7 | 制約 | シェルスクリプトはbash構文に準拠すること |
| 8 | 制約 | 機密情報（本番IPアドレス・パスワード・SSH秘密鍵等）はシェルスクリプトにハードコードしない |
| 9 | 制約 | サーバAのCommandA.sh処理が正常終了しない限り、サーバBへの処理を実行しない |
| 10 | スコープ外 | 外部シェル連携結果の取得・確認は本プロジェクトのスコープ外とする |
| 11 | スコープ外 | SSH接続のための公開鍵配布・証明書管理（事前設定済みを前提とする） |
| 12 | スコープ外 | サーバA・サーバBのOS・ネットワーク設定・インフラ管理 |
