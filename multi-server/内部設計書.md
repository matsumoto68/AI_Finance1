## 3. CommandA.sh 内部設計

> CommandA.shはsingle-server版と同一の内部設計である。詳細は **single-server/内部設計書.md** セクション3〜4を参照。

### 3.1 全体構造

```bash
#!/bin/bash
# ============================================================
# CommandA.sh - リリース作業自動化シェルスクリプト（サーバA向け）
# ============================================================

set -u

# --- 定数定義 ---
LOG_DIR="/var/log/release"
TIMESTAMP=$(date +%Y%m%d%H%M%S)
LOG_FILE="${LOG_DIR}/CommandA_${TIMESTAMP}.log"
DETAIL_LOG="${LOG_DIR}/CommandA_detail_${TIMESTAMP}.log"
WORK_DIR="/tmp/testdir"
WORK_DIR_BK="/tmp/testdir_bk"
TARGET_FILE="${WORK_DIR}/test.txt"
DATA_FILE="${WORK_DIR}/data.txt"
DATA_BK_FILE="${WORK_DIR}/data_bk.txt"
RENAMED_FILE="${WORK_DIR}/renamed.txt"
TARGET_SH="/tmp/testfile.sh"
SERVICE_NAME="nginx"

# --- 関数定義 ---
log_info()   { ... }   # INFOログ出力
log_error()  { ... }   # ERRORログ出力
log_cmd()    { ... }   # コマンドログ出力
log_rc()     { ... }   # ReturnCodeログ出力
check_rc()   { ... }   # ReturnCodeチェック・エラー処理
check_str()  { ... }   # 出力文字列チェック・エラー処理

# --- メイン処理 ---
main() {
    init_log          # ログ初期化
    check_env         # 事前チェック
    proc_dir          # ディレクトリ操作処理
    proc_file         # ファイル操作処理
    proc_service      # サービス操作処理
    proc_misc         # 一覧表示・権限変更処理
    log_info "処理正常終了"
    exit 0
}

main
```

### 3.2 定数定義

| 定数名 | 値 | 説明 |
|--------|----|------|
| `LOG_DIR` | `/var/log/release` | ログ出力ディレクトリ |
| `LOG_FILE` | `/var/log/release/CommandA_YYYYMMDDHHMMSS.log` | シェル実行ログ |
| `DETAIL_LOG` | `/var/log/release/CommandA_detail_YYYYMMDDHHMMSS.log` | 詳細ログ |
| `WORK_DIR` | `/tmp/testdir` | 作業ディレクトリ |
| `WORK_DIR_BK` | `/tmp/testdir_bk` | バックアップディレクトリ |
| `TARGET_FILE` | `/tmp/testdir/test.txt` | 操作対象ファイル（touch用） |
| `DATA_FILE` | `/tmp/testdir/data.txt` | データファイル |
| `DATA_BK_FILE` | `/tmp/testdir/data_bk.txt` | データバックアップファイル |
| `RENAMED_FILE` | `/tmp/testdir/renamed.txt` | リネーム後ファイル |
| `TARGET_SH` | `/tmp/testfile.sh` | 権限変更対象シェル |
| `SERVICE_NAME` | `nginx` | 操作対象サービス名 |

### 3.3 共通関数設計

| 関数名 | 役割 | 引数 | 処理内容 | 出力先 |
|--------|------|------|---------|--------|
| `log_info()` | INFOログ出力 | `$1`：ログメッセージ | タイムスタンプ取得 → `[INFO] メッセージ` 形式でログ追記 → 標準出力にも出力 | `LOG_FILE` + 標準出力 |
| `log_error()` | ERRORログ出力 | `$1`：エラーメッセージ | タイムスタンプ取得 → `[ERROR] メッセージ` 形式でログ追記 → 標準エラー出力にも出力 | `LOG_FILE` + 標準エラー出力 |
| `log_cmd()` | コマンドログ出力 | `$1`：実行コマンド文字列 | `[CMD] コマンド文字列` 形式でログ追記 | `DETAIL_LOG` |
| `log_rc()` | ReturnCodeログ出力 | `$1`：ReturnCode値 | `[RC] ReturnCode=N` 形式でログ追記 | `DETAIL_LOG` |
| `check_rc()` | ReturnCodeチェック | `$1`：実際のRC（`$?`）<br>`$2`：期待するRC<br>`$3`：エラーコード<br>`$4`：エラーメッセージ | RC比較 → 不一致の場合 `log_error()` + `log_rc()` → `exit 1` | `LOG_FILE` / `DETAIL_LOG` |
| `check_str()` | 出力文字列チェック | `$1`：確認対象文字列（コマンド出力）<br>`$2`：確認文字列<br>`$3`：チェック種別（`must_contain` / `must_not_contain`）<br>`$4`：エラーコード<br>`$5`：エラーメッセージ | grepで確認文字列を検索 → チェック種別に応じてエラー判定 → エラーの場合 `log_error()` → `exit 1` | `LOG_FILE` |

> **実装上の注意（ベストプラクティス）：**
> `$?` はコマンド実行直後に `rc=$?` で変数に退避してから `check_rc "${rc}" ...` のように渡すこと。
> `$?` はコマンド実行のたびに上書きされるため、関数呼び出しや別処理を挟む前に必ず退避する。

### 3.4 初期化処理（init_log）

```
【処理】
  1. LOG_DIRが存在しない場合、mkdir -p で作成
  2. LOG_DIRへの書き込み権限確認（権限なし → E001エラー終了）
  3. LOG_FILE・DETAIL_LOG のヘッダー行を出力
     （実行開始日時・スクリプト名）
```

### 3.5 事前チェック処理（check_env）

```
【処理】
  1. systemctl コマンドの存在確認
     → 存在しない場合: E002エラーログ出力・exit 1
```

### 3.6 各処理の詳細設計

> CommandA.shの各処理詳細（proc_dir / proc_file / proc_service / proc_misc）は single-server版内部設計書 セクション4と同一のため、そちらを参照。

### 4.6 各処理の詳細設計

CommandA.shと同等の処理構造（proc_dir / proc_file / proc_service / proc_misc）を持つ。各ステップの処理内容・エラー処理はCommandA.shと同一。

#### ディレクトリ操作処理（proc_dir）

| ステップ | 処理内容 | 実行コマンド | エラー処理 |
|---------|---------|------------|----------|
| 1 | ディレクトリ作成（正常） | `mkdir ${WORK_DIR}` | RC≠0 → エラー終了 |
| 2 | ディレクトリ作成（既存・エラー確認） | `mkdir ${WORK_DIR} 2>&1` | 出力に `File exists` → エラー終了 |
| 3 | ディレクトリ作成（権限なし・エラー確認） | `mkdir /root/noperm 2>&1` | 出力に `Permission denied` → エラー終了 |
| 4 | ディレクトリ移動（正常） | `cd ${WORK_DIR}` | RC≠0 → エラー終了 |
| 5 | ディレクトリ移動（不存在・エラー確認） | `cd /tmp/notexist 2>&1` | 出力に `No such file or directory` → エラー終了 |
| 6 | ディレクトリコピー | `cp -r ${WORK_DIR} ${WORK_DIR_BK}` | RC≠0 → エラー終了 |
| 7 | ディレクトリ削除（空） | `rmdir ${WORK_DIR_BK}` | RC≠0 → エラー終了 |
| 7.5 | D-08前処理: WORK_DIR配下にファイル作成（非空状態にする） | `touch ${WORK_DIR}/dummy.txt` | RC≠0 → エラー終了 |
| 8 | ディレクトリ削除（非空・エラー確認） | `rmdir ${WORK_DIR} 2>&1` | 出力に `Directory not empty` → エラー終了 |
| 9 | ディレクトリ強制削除 | `rm -rf ${WORK_DIR}` | RC≠0 → エラー終了 |

#### ファイル操作処理（proc_file）

| ステップ | 処理内容 | 実行コマンド | エラー処理 |
|---------|---------|------------|----------|
| 1 | ファイル作成（touch） | `touch ${TARGET_FILE}` | RC≠0 → エラー終了 |
| 2 | ファイル作成（echo） | `echo hello > ${DATA_FILE}` | RC≠0 → エラー終了 |
| 3 | ファイル内容確認 | `cat ${DATA_FILE}` | 出力に `hello` が含まれない → エラー終了 |
| 4 | ファイルコピー | `cp ${DATA_FILE} ${DATA_BK_FILE}` | RC≠0 → エラー終了 |
| 5 | ファイルコピー（上書き） | `cp -f ${DATA_FILE} ${DATA_BK_FILE}` | RC≠0 → エラー終了 |
| 6 | ファイル移動（リネーム） | `mv ${TARGET_FILE} ${RENAMED_FILE}` | RC≠0 → エラー終了 |
| 7 | ファイル削除 | `rm ${DATA_BK_FILE}` | RC≠0 → エラー終了 |
| 8 | ファイル削除（不存在・エラー確認） | `rm /tmp/testdir/notexist.txt 2>&1` | 出力に `No such file or directory` → エラー終了 |
| 9 | 作業ディレクトリ強制削除（ゴミファイル削除） | `rm -rf ${WORK_DIR}` | RC≠0 → エラー終了 |

#### サービス操作処理（proc_service）

| ステップ | 処理内容 | 実行コマンド | エラー処理 |
|---------|---------|------------|----------|
| 1 | サービス起動 | `systemctl start ${SERVICE_NAME}` | RC≠0 → エラー終了 |
| 2 | サービス起動失敗確認 | `systemctl start ${SERVICE_NAME} 2>&1` | 出力に `Failed` → エラー終了 |
| 3 | 起動確認 | `systemctl is-active ${SERVICE_NAME}` | 出力に `active` が含まれない → エラー終了 |
| 4 | サービス停止 | `systemctl stop ${SERVICE_NAME}` | RC≠0 → エラー終了 |
| 5 | 停止確認 | `systemctl is-active ${SERVICE_NAME}` | 出力に `inactive` が含まれない → エラー終了 |
| 6 | サービス状態確認 | `systemctl status ${SERVICE_NAME}` | 出力に `Active` が含まれない → エラー終了 |

#### 一覧表示・権限変更処理（proc_misc）

| ステップ | 処理内容 | 実行コマンド | エラー処理 |
|---------|---------|------------|----------|
| 1 | 一覧表示 | `ls -la /tmp` | 出力に `total` が含まれない → エラー終了 |
| 2 | ファイル権限変更 | `chmod 755 ${TARGET_SH}` | RC≠0 → エラー終了 |

## 5. release_all.sh 内部設計

### 5.1 全体構造

```bash
#!/bin/bash
# ============================================================
# release_all.sh - オーケストレーターシェル（複数サーバ一括制御）
# ============================================================

set -u

# --- 定数定義 ---
LOG_DIR="/var/log/release"
TIMESTAMP=$(date +%Y%m%d%H%M%S)
LOG_FILE="${LOG_DIR}/release_all_${TIMESTAMP}.log"
DETAIL_LOG="${LOG_DIR}/release_all_detail_${TIMESTAMP}.log"
SCRIPT_DIR="/opt/release/scripts"
COMMAND_A="${SCRIPT_DIR}/CommandA.sh"
COMMAND_B="${SCRIPT_DIR}/CommandB.sh"
REMOTE_SCRIPT_DIR="/opt/release/scripts"

# --- 接続情報（外部から取得） ---
SERVER_B_HOST=""
SERVER_B_USER=""
SERVER_B_KEY=""
SSH_TIMEOUT=10

# --- 関数定義 ---
log_info()       { ... }   # INFOログ出力
log_error()      { ... }   # ERRORログ出力
log_cmd()        { ... }   # コマンドログ出力
log_rc()         { ... }   # ReturnCodeログ出力
check_rc()       { ... }   # ReturnCodeチェック・エラー処理
load_config()    { ... }   # 接続情報の読み込み

# --- メイン処理 ---
main() {
    init_log              # ログ初期化
    load_config           # 接続情報読み込み
    check_env             # 事前チェック（SSH接続確認含む）
    exec_server_a         # サーバA処理（CommandA.sh実行）
    transfer_to_server_b  # サーバBへ資材転送（SCP）
    exec_server_b         # サーバBリモート実行（SSH）
    log_info "処理正常終了"
    exit 0
}

main
```

### 5.2 定数定義

| 定数名 | 値 | 説明 |
|--------|----|------|
| `LOG_DIR` | `/var/log/release` | ログ出力ディレクトリ |
| `LOG_FILE` | `/var/log/release/release_all_YYYYMMDDHHMMSS.log` | オーケストレーターシェル実行ログ |
| `DETAIL_LOG` | `/var/log/release/release_all_detail_YYYYMMDDHHMMSS.log` | オーケストレーター詳細ログ |
| `SCRIPT_DIR` | `/opt/release/scripts` | ローカルスクリプト配置ディレクトリ |
| `COMMAND_A` | `/opt/release/scripts/CommandA.sh` | サーバA向けメインシェルのパス |
| `COMMAND_B` | `/opt/release/scripts/CommandB.sh` | サーバB向けメインシェルのパス（SCP転送元） |
| `REMOTE_SCRIPT_DIR` | `/opt/release/scripts` | サーバB上のスクリプト配置ディレクトリ |
| `SERVER_B_HOST` | （外部から取得） | サーバBのホスト名またはIPアドレス |
| `SERVER_B_USER` | （外部から取得） | サーバBへのSSH接続ユーザー |
| `SERVER_B_KEY` | （外部から取得） | SSH認証用秘密鍵ファイルのパス |
| `SSH_TIMEOUT` | `10` | SSH接続タイムアウト（秒） |

### 5.3 共通関数設計

`log_info()`・`log_error()`・`log_cmd()`・`log_rc()`・`check_rc()` はCommandA.shと同一の仕様。出力先がrelease_all.sh用のログファイルに変わる。

### 5.4 接続情報読み込み（load_config）

```
【処理】
  1. 設定ファイルまたは実行時引数から接続情報を取得
     - SERVER_B_HOST（ホスト名）
     - SERVER_B_USER（ユーザー名）
     - SERVER_B_KEY（秘密鍵パス）
  2. 各値が空でないことを確認
     → 空の場合: エラーログ出力・exit 1
  3. 秘密鍵ファイルの存在確認
     → 存在しない場合: エラーログ出力・exit 1
```

> ※ 接続情報はシェルスクリプト内にハードコードしない。設定ファイルまたは実行時パラメータから取得する。

### 5.5 初期化処理（init_log）

CommandA.shと同一の構造。ヘッダー出力のスクリプト名が `release_all.sh` に変わる。

### 5.6 事前チェック処理（check_env）

```
【処理】
  1. CommandA.shの存在確認
     → 存在しない場合: エラーログ出力・exit 1
  2. CommandB.shの存在確認
     → 存在しない場合: エラーログ出力・exit 1
  3. サーバBへのSSH接続確認
     実行コマンド: ssh -o ConnectTimeout=${SSH_TIMEOUT} -i ${SERVER_B_KEY} ${SERVER_B_USER}@${SERVER_B_HOST} "echo ok"
     → 出力に "ok" が含まれない場合: エラーログ出力・exit 1
```

### 5.7 各処理の詳細設計

#### サーバA処理（exec_server_a）

| ステップ | 処理内容 | 実行コマンド | エラー処理 |
|---------|---------|------------|----------|
| 1 | CommandA.shをローカル実行 | `bash ${COMMAND_A}` | RC≠0 → エラーログ出力・サーバB処理を実行せずにexit 1 |

```
【処理】
  1. log_info "サーバA処理 開始"
  2. log_cmd "bash ${COMMAND_A}"
  3. bash ${COMMAND_A} を実行
  4. rc=$? でReturnCode退避
  5. log_rc "${rc}"
  6. RC≠0の場合:
     - log_error "サーバA処理失敗: CommandA.sh (RC=${rc})"
     - log_info "サーバB処理はスキップします"
     - exit 1
  7. log_info "サーバA処理 完了"
```

#### サーバBへの資材転送（transfer_to_server_b）

| ステップ | 処理内容 | 実行コマンド | エラー処理 |
|---------|---------|------------|----------|
| 1 | CommandB.shをサーバBへSCP転送 | `scp -i ${SERVER_B_KEY} ${COMMAND_B} ${SERVER_B_USER}@${SERVER_B_HOST}:${REMOTE_SCRIPT_DIR}/` | RC≠0 → エラーログ出力・exit 1 |

```
【処理】
  1. log_info "サーバBへの資材転送 開始"
  2. log_cmd "scp -i ${SERVER_B_KEY} ${COMMAND_B} ${SERVER_B_USER}@${SERVER_B_HOST}:${REMOTE_SCRIPT_DIR}/"
  3. scp を実行
  4. rc=$? でReturnCode退避
  5. log_rc "${rc}"
  6. RC≠0の場合:
     - log_error "SCP転送失敗: CommandB.sh → サーバB (RC=${rc})"
     - exit 1
  7. log_info "サーバBへの資材転送 完了"
```

#### サーバBリモート実行（exec_server_b）

| ステップ | 処理内容 | 実行コマンド | エラー処理 |
|---------|---------|------------|----------|
| 1 | サーバB上のCommandB.shをSSHリモート実行 | `ssh -i ${SERVER_B_KEY} ${SERVER_B_USER}@${SERVER_B_HOST} "bash ${REMOTE_SCRIPT_DIR}/CommandB.sh"` | RC≠0 → サーバBのエラー内容をサーバAログに記録・exit 1 |

```
【処理】
  1. log_info "サーバBリモート実行 開始"
  2. log_cmd "ssh -i ${SERVER_B_KEY} ${SERVER_B_USER}@${SERVER_B_HOST} bash ${REMOTE_SCRIPT_DIR}/CommandB.sh"
  3. ssh を実行（出力をキャプチャ）
  4. rc=$? でReturnCode退避
  5. log_rc "${rc}"
  6. RC≠0の場合:
     - log_error "サーバBリモート実行失敗: CommandB.sh (RC=${rc})"
     - サーバBのエラー出力をオーケストレーターログに記録
     - exit 1
  7. log_info "サーバBリモート実行 完了"
```

## 6. deploy_multi.sh 内部設計

### 6.1 全体構造

```bash
#!/bin/bash
# ============================================================
# deploy_multi.sh - 複数サーバ向け資材配置シェル
# ============================================================

set -u

# --- 定数定義 ---
SCRIPT_DIR="/opt/release/scripts"
SRC_COMMAND_A="./CommandA.sh"
SRC_COMMAND_B="./CommandB.sh"
SRC_RELEASE_ALL="./release_all.sh"

# --- メイン処理 ---
main() {
    check_src      # 配置元ファイル存在確認
    make_dir       # 配置先ディレクトリ作成（存在しない場合）
    copy_files     # ファイルコピー
    set_permission # 実行権限付与
    echo "配置完了: ${SCRIPT_DIR}"
    exit 0
}

main
```

### 6.2 定数定義

| 定数名 | 値 | 説明 |
|--------|----|------|
| `SCRIPT_DIR` | `/opt/release/scripts` | 配置先ディレクトリ |
| `SRC_COMMAND_A` | `./CommandA.sh` | CommandA.sh の配置元パス |
| `SRC_COMMAND_B` | `./CommandB.sh` | CommandB.sh の配置元パス |
| `SRC_RELEASE_ALL` | `./release_all.sh` | release_all.sh の配置元パス |

### 6.3 各処理詳細

| 関数名 | 処理内容 | 実行コマンド | エラー処理 |
|--------|---------|------------|----------|
| `check_src` | 配置元ファイル存在確認（3ファイル） | `[ -f ${SRC_COMMAND_A} ]`<br>`[ -f ${SRC_COMMAND_B} ]`<br>`[ -f ${SRC_RELEASE_ALL} ]` | いずれかのファイルが存在しない場合: エラーメッセージ出力・`exit 1` |
| `make_dir` | 配置先ディレクトリ作成 | `[ -d ${SCRIPT_DIR} ]`<br>存在しない場合: `mkdir -p ${SCRIPT_DIR}` | `mkdir` 失敗（RC≠0）の場合: エラーメッセージ出力・`exit 1` |
| `copy_files` | 3ファイルをコピー | `cp ${SRC_COMMAND_A} ${SCRIPT_DIR}/CommandA.sh`<br>`cp ${SRC_COMMAND_B} ${SCRIPT_DIR}/CommandB.sh`<br>`cp ${SRC_RELEASE_ALL} ${SCRIPT_DIR}/release_all.sh` | いずれかのコピーでRC≠0の場合: エラーメッセージ出力・`exit 1` |
| `set_permission` | 実行権限付与（3ファイル） | `chmod 755 ${SCRIPT_DIR}/CommandA.sh`<br>`chmod 755 ${SCRIPT_DIR}/CommandB.sh`<br>`chmod 755 ${SCRIPT_DIR}/release_all.sh` | いずれかでRC≠0の場合: エラーメッセージ出力・`exit 1` |

## 8. 処理シーケンス

### 8.1 release_all.sh 処理シーケンス

```
release_all.sh 起動
    │
    ├─ init_log()
    │     ├─ LOG_DIR 存在確認・作成
    │     └─ ログヘッダー出力
    │
    ├─ load_config()
    │     ├─ 接続情報の読み込み（ホスト名・ユーザー名・秘密鍵パス）
    │     ├─ 空値チェック
    │     └─ 秘密鍵ファイル存在確認
    │
    ├─ check_env()
    │     ├─ CommandA.sh 存在確認
    │     ├─ CommandB.sh 存在確認
    │     └─ サーバBへのSSH接続確認（echo ok）
    │
    ├─ exec_server_a()
    │     └─ bash CommandA.sh をローカル実行
    │         ├─ 正常終了 → 次へ
    │         └─ 異常終了 → サーバB処理スキップ・exit 1
    │
    ├─ transfer_to_server_b()
    │     └─ SCP: CommandB.sh → サーバB /opt/release/scripts/
    │         ├─ 正常終了 → 次へ
    │         └─ 異常終了 → exit 1
    │
    ├─ exec_server_b()
    │     └─ SSH: サーバB上の CommandB.sh をリモート実行
    │         ├─ 正常終了 → 次へ
    │         └─ 異常終了 → サーバBエラー内容をサーバAログに記録・exit 1
    │
    └─ exit 0（正常終了）
```

### 8.2 CommandA.sh 処理シーケンス

```
CommandA.sh 起動
    │
    ├─ init_log()
    │     ├─ LOG_DIR 存在確認・作成
    │     └─ ログヘッダー出力
    │
    ├─ check_env()
    │     └─ systemctlコマンド存在チェック
    │
    ├─ proc_dir()
    │     ├─ 項番1〜3: ディレクトリ作成系
    │     ├─ 項番7〜8: ディレクトリ移動系
    │     ├─ 項番11: ディレクトリコピー
    │     └─ 項番15〜17: ディレクトリ削除系
    │
    ├─ proc_file()
    │     ├─ 項番4〜6: ファイル作成・確認
    │     ├─ 項番9〜10: ファイルコピー
    │     ├─ 項番12: ファイル移動
    │     └─ 項番13〜14: ファイル削除
    │
    ├─ proc_service()
    │     ├─ 項番18〜19: サービス起動
    │     ├─ 項番20: 起動確認
    │     ├─ 項番21: サービス停止
    │     ├─ 項番22: 停止確認
    │     └─ 項番23: サービス状態確認
    │
    ├─ proc_misc()
    │     ├─ 項番24: 一覧表示
    │     └─ 項番25: 権限変更
    │
    └─ exit 0（正常終了）
         ※ エラー発生時は各処理内で exit 1
```

### 8.3 CommandB.sh 処理シーケンス

CommandA.shと同一の処理シーケンス。ヘッダー出力のスクリプト名が `CommandB.sh` に変わる。

### 8.4 deploy_multi.sh 処理シーケンス

```
deploy_multi.sh 起動
    │
    ├─ check_src()
    │     ├─ CommandA.sh 存在確認
    │     ├─ CommandB.sh 存在確認
    │     └─ release_all.sh 存在確認
    │
    ├─ make_dir()
    │     └─ /opt/release/scripts/ 存在確認・作成
    │
    ├─ copy_files()
    │     ├─ CommandA.sh → /opt/release/scripts/CommandA.sh
    │     ├─ CommandB.sh → /opt/release/scripts/CommandB.sh
    │     └─ release_all.sh → /opt/release/scripts/release_all.sh
    │
    ├─ set_permission()
    │     ├─ chmod 755 CommandA.sh
    │     ├─ chmod 755 CommandB.sh
    │     └─ chmod 755 release_all.sh
    │
    └─ exit 0（正常終了）
         ※ エラー発生時は各処理内で exit 1
```
